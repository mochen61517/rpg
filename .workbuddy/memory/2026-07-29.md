## v4.4：任务分「时间驱动型」vs「固定型」两种模式
- 用户需求：身体训练/唱歌这类时间不固定的活动，应是"项目"——自己填实际时长（分钟），按时间长度算经验；23:30前睡觉/补剂这类固定动作按固定经验值算。之前是统一固定 xp 勾选，对"做45min还是30min一样分"不公平。
- 实现：给每个 checklist 项加 `mode` 字段（`'time'`/`'fixed'`）。
  - time 型：渲染为「分钟输入框 + 完成/撤销按钮」，点完成时读输入框分钟数 → 经验 = 分钟 × RATE(=1 原始经验/分钟)，整体汇总时再 ×版块权重。做多久给多少。
  - fixed 型：保持原勾选框，done 给固定 xp。
  - 经验率常量 `RATE=1`（原始经验/分钟）；辅助 `itemXp(it)`（time→min×RATE，fixed→xp）、`weightedXp(it)`（×权重）。
  - 默认数据：daily 身体训练/心流/成长行动=time，睡觉=fixed；weekly 羽毛球对抗/视频/AI/求职/唱歌/阅读=time，播客上限=fixed；补剂=fixed；年/月/周主线步骤按"有实际耗时意义"设 time（网申/笔面/面试/做功课/写复盘等），纯事件（拿offer/入职/付费客户）设 fixed。
  - `addQuest`：填了分钟→time，没填→fixed（supps 无分钟输入→永远 fixed，符合）。`addChecklistItem`：新增步骤表单加「时间驱动/固定XP」下拉 + 分钟/XP 输入。
  - `load()` 兼容旧存档：无 mode 字段的旧项按 min>0 自动补 time，否则 fixed。
- 验证（node DOM 桩实跑）：time 身体训练45min→VIT+45、整体+27(×0.6)；撤销精确回退；fixed 睡觉→ORD+10；checklist time 年1网申60min→GRW+60、整体+90(×1.5)；fixed 拿offer→GRW+100、整体+150；render 含 min_ 输入框不崩；旧存档无 mode→自动补——全部 PASSED。

## v4.5：总等级继承历史（用户选方案 B）
- 用户此前问"为何总等级 Lv1"，给了 A(保持)/B(继承历史折算) 两选项；本次明确"倾向 b 继承历史"。
- 实现：总等级不再是"从零开始"。`overallXP()` 增加 `inheritedXP()` 项 = Σ(历史小时[k] × 权重[k]) × HISTORY_RATE。
  - `HISTORY_HOURS`：把 iHour 终身 4234h 按五维拆分（与 time-analysis.md 口径一致）——VIT 1771 / FLOW 670 / GRW 1512 / ORD 281 / CON 0（终身记录未单列 CON 大项）。拆分：羽毛球1649(实战1154→VIT + 视频495→GRW)、身体881(训练600→VIT + 心理281→ORD)、职业495→GRW、教练474→GRW、艺术488→FLOW、阅读182→FLOW、海外48→GRW、体态17→VIT。五维合计=4234h 闭合。
  - `HISTORY_RATE=3`（默认）：每历史小时 × 版块权重 × 3 = 继承加权经验。设计为"压缩折算"——若与当前打卡同口径(分钟×权重)历史会爆到 Lv70+，淹没每日打卡；压缩后默认 Lv17，既体现资深积累又保留每日反馈空间。
  - 等级分工：五维条(体魄/心流/成长/秩序)每次打勾**即时变动**，承担"每次打卡的反馈感"；总等级是**终身成就象征**，缓升（Lv17→18 约需全勤 18 天）。
  - 总进度面板新增 `histInherit` 提示行，透明展示继承来源与数值；`weightHint` 文案改为"整体等级 = 五维活跃经验 + 历史继承底分"。
